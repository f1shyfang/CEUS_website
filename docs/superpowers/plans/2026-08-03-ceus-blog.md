# CEUS Blog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a public CEUS blog for news, student guides, and careers articles, with publishing managed through the existing administrator dashboard.

**Architecture:** Persist Markdown-authored posts in a Supabase `blog_posts` table, enforce public visibility with row-level security, and expose focused repository functions from the existing Supabase module. Server-rendered Next.js routes provide the index and article pages; a small client component filters already-published posts without a navigation. The existing client-side admin patterns provide post CRUD, image upload, and featured-post management.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, Tailwind CSS 3, Supabase, Zod, React Hook Form, `next/font`, Vitest, Testing Library, React Markdown.

## Global Constraints

- Use Australian English in all visitor-facing CEUS copy.
- The three categories are exactly `news`, `student-guides`, and `careers-industry`; display labels are CEUS News, Student Guides, and Careers & Industry.
- Store article bodies as CommonMark Markdown; render them without raw HTML support.
- Retain Inter for UI and add Literata only for reading/editorial text.
- The blog has no newsletter, comments, reactions, account, paywall, or search feature.
- Published public queries must exclude drafts in application code and via Supabase row-level security.
- Meet WCAG 2.2 AA: semantic headings, visible focus, 4.5:1 normal-text contrast, keyboard-operable filters, descriptive image alt text, and reduced-motion-safe interactions.
- Use the `public-images` storage bucket in a `blog` folder for optional cover images.

Add unique `slug`, a partial unique index for a featured published post, and descending indexes on `published_at` and `(category, published_at)`. Reuse the jobs migration's `updated_at` trigger pattern.

Enable RLS with these policies: anonymous/public users can select only `status = 'published'`; authenticated users can select every post and insert, update, and delete posts. Implement this atomic RPC so choosing a new feature cannot temporarily violate the unique index:

```sql
create or replace function public.set_featured_blog_post(target_post_id uuid)
returns public.blog_posts
language plpgsql
security invoker
as $$
declare selected_post public.blog_posts;
begin
  update public.blog_posts set is_featured = false where is_featured = true;
  update public.blog_posts
    set is_featured = true
    where id = target_post_id and status = 'published'
    returning * into selected_post;
  if selected_post.id is null then
    raise exception 'Featured post must exist and be published';
  end if;
  return selected_post;
end;
$$;
```

In `supabase.ts`, select only explicit blog columns and always add `.eq('status', 'published')` to public list and slug queries. Map snake_case fields through `toBlogPost`. The admin list orders by `updated_at` descending. The create and update payloads never expose `is_featured` directly; call the RPC only after a successful publish/update where the form requests a feature. Store cover image URLs as `null` when the form submits an empty string.
